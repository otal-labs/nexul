---
name: Writing a doc
description: Use when writing or rewriting a doc that proposes an idea or a feature, before it is cut into tickets.
always_included: false
footer: false
---

A doc is finished when a developer could cut tickets from it without asking its authors anything.

- Open with the problem and who has it. Then list what they will be able to do, each a plain sentence someone could check.
- Say what is out of scope. List what is still undecided under "Open points" instead of guessing.
- Leave out how to build it: no file paths, code or library choices.
- When you edit a doc, keep the authors' sentences that still hold, and add only what they said or confirmed.
- One feature per doc. Flag a second one under "Open points" instead of splitting an author's doc.
